# Contributing

## How to contribute

1. Open an issue describing the gap (missing control, outdated reference, unclear checklist item)
2. Prefer small PRs that touch one domain
3. Every new **P0** rule must be:
   - verifiable (checklist-friendly)
   - linked to a recognized reference when possible
   - accompanied by Detect / Verify guidance in the domain doc

## PR requirements

- [ ] Clear problem statement
- [ ] No weakening of P0 security/authz/backup controls without explicit migration notes
- [ ] Docs and checklists stay in sync
- [ ] Examples stay stack-realistic (Node/TS + Postgres + React preferred)

## Code of conduct

Be respectful. Focus on engineering outcomes, not personalities or brands.
